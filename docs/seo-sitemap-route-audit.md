# Sitemap route audit (2026-10-01)

The pre-change router has **55 file routes** (`src/routes`, excluding `__root.tsx` and its 404/error boundaries). Route files, not expanded product/category records, are counted here. The new `/sitemap.xml` utility route makes the post-change count 56. The sitemap includes 8 static route templates and expands 2 dynamic templates from live public catalog data; the other 45 pre-change route files are excluded.

There is no standalone 404 route: the root router provides a 404/error boundary. No previous sitemap implementation or canonical link tags were found. The root redirect is deliberately not duplicated as a sitemap entry. `/categorie/pungi-hartie` is an old redirect to `/categorie/pungi-fara-maner`; only currently visible category slugs from the database are emitted.

The existing product listing queries `status = published` and `is_archived = false`; the sitemap uses those same filters. The existing category listing queries `is_visible = true`; the sitemap does likewise. Both are fetched via a dedicated anonymous publishable-key client on the server, never a service-role key. The `updated_at` columns are maintained by database triggers, so they are suitable for product/category `lastmod`; no static-page modification dates are invented. Slugs are restricted to single lowercase hyphenated path segments and URLs are deduplicated.

At audit time the public catalog returned 5 visible categories and 63 published, non-archived products. Thus the expected sitemap has **76 URLs** (8 + 5 + 63). Counts change with catalog content. The requested `.ro` domain did not return a usable HTTP response and had no A record in the local DNS check; production reachability must be verified after the domain is connected and this branch is deployed.
